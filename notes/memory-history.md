## Figma API gotchas (full)

## Text node names auto-sync to content
**Rule:** In Figma Plugin API, when you set `textNode.characters = 'Foo'`, the node's `.name` property automatically becomes `'Foo'`. Explicitly setting `node.name = 'CustomName'` afterwards does NOT persist — Figma reverts it back to the text content.

**Why:** Figma's plugin runtime mirrors the canvas layer-naming behaviour where text layers are named after their content.

**How to apply:** Never use `findOne(n => n.name === 'Nav_Title')` to locate a text node inside a component/instance — it will always fail. Instead traverse by child index or search by current text content: `findOne(n => n.type === 'TEXT' && n.characters === 'Page Title')`.

---

## Load font FROM the node before setting characters
**Rule:** Always do `await figma.loadFontAsync(node.fontName)` before setting `node.characters` on a text node inside an instance. Loading by your own style string (e.g. 'Semi Bold') may differ from what Figma stores internally (e.g. 'SemiBold'). Wrap in try/catch otherwise silent failures occur.

**Why:** Figma stores font style strings in its own normalised form. A mismatch causes a silent error when `characters` is set.

**How to apply:** Pattern to always use:
```javascript
if (node.fontName !== figma.mixed) {
  await figma.loadFontAsync(node.fontName);
}
node.characters = newText;
```

---

## primaryAxisSizingMode: use 'AUTO' not 'HUG'
**Rule:** The valid values for `primaryAxisSizingMode` and `counterAxisSizingMode` are `'FIXED'` and `'AUTO'` — NOT `'HUG'`. Using `'HUG'` throws `Invalid enum value`.

**Why:** The Figma Plugin API uses `'AUTO'` where the UI shows "Hug contents".

**How to apply:** Replace all `'HUG'` with `'AUTO'` in sizing mode assignments.

---

## Stroke fill must use explicit RGB, not hex helper
**Rule:** When setting `.strokes`, use explicit `{r, g, b}` objects, not a hex-string helper function: `c.strokes = [{type:'SOLID', color: hex('#cc2535')}]`. Never pass `{r:0,g:0,b:0}` directly — use `{r:0.001,g:0.001,b:0.001}` or a child rectangle with opacity instead.

**Why:** The Figma API validates stroke colour objects strictly and some helper functions produce `NaN` values for the `.b` channel.

---

## prototype actions: use `actions` array, never `action`
**Rule:** Prototype connections must use `actions: [{...}]` (array), never `action: {...}` (singular). Figma silently rejects the singular form.

**Why:** The API schema requires an array even for single actions.

---

## Overlay scrim: use child rectangle with opacity, not fill opacity on frame
**Rule:** For dark scrims on overlay frames, set `frame.fills = []` (transparent frame) and add a child `figma.createRectangle()` with a dark fill and set `scrim.opacity = 0.65` on the rectangle node.

**Why:** Setting opacity directly on a fill object causes NaN errors in some contexts.

---

## createImage(bytes) images don't persist via the MCP
**Rule:** `figma.createImage(await node.exportAsync(...))` returns a hash, but the image never uploads. Fills using it render blank (and `get_screenshot` returns a 1×1).

**Why:** Hit on 2026-10-12 while trying to flatten a composite hero. It had to be reverted.

**How to apply:** don't generate raster images in-plugin. Build composites as frames of existing image fills, and let the user export from Figma.

---

## Binding width/height on a MAIN component turns instances' Fill into Fixed
**Rule:** `mainComponent.setBoundVariable('width', v)` pushes the binding to every instance. Instances that were FILL become FIXED at the token value. They overflow on Tablet/Mobile, but desktop often looks fine because the widths happen to match. Text max-width also can't be bound (`invalid field for text node: 'maxWidth'`), and GROUP sizes can't be bound.

**Why:** Hit twice on 2026-10-12, first on Menu Button (Mobile Menu buttons) and then on Section Header, Project Detail, Feature Image(s) and Image Enlarge Overlay. Each time it needed a repair pass.

**How to apply:** Before binding a component's width/height, list its instances. Then either bind only on instances that are genuinely FIXED, or immediately re-run `inst.setBoundVariable('width', null); inst.layoutSizingHorizontal = 'FILL'` on instances in auto-layout parents (component descriptions say "FILL"). Verify with an overflow scan (child width > parent inner width), not frame heights alone. Skip aspect-locked nodes (`targetAspectRatio`), whose heights are derived.

**Cloning a frame copies its prototype flow starting point** (2026-10-15): `frame.clone()` of a flow-start frame adds a duplicate entry to `page.flowStartingPoints` with the same name, so Present view lists several identically named flows. After cloning screens, check `page.flowStartingPoints` and remove the clones' entries (reassign the array). Dan noticed this in Present view.

**findAll on a screen frame reaches inside instances** (2026-10-15): `frame.findAll(n => n.type==='TEXT' && n.parent.type!=='INSTANCE')` still returns Nav bar link texts (their parent is the Links FRAME inside the instance). Writing to them overrides the nav. Scope text edits to the frame's own Content child, or walk up the parent chain to exclude anything inside an INSTANCE. Fix if it happens: `navInstance.resetOverrides()`. Same for reactions: rewiring "every link to G1" also hits the nav's Teachers link.

**Turning a horizontal auto-layout row into a vertical column** (2026-10-15): after `layoutMode = 'VERTICAL'` on an existing row, Dan's Figma client kept the old one-line height and clipped everything but the first item, though screenshots looked fine. Fix: set `clipsContent = false` and explicitly set `primaryAxisSizingMode`/`counterAxisSizingMode = 'AUTO'` (and `layoutSizingVertical/Horizontal = 'HUG'`) on the frame and its parent right after the change.

**Bind colour variables with the real colour as the base paint** (2026-10-15): `setBoundVariableForPaint({type:'SOLID',color:{r:0,g:0,b:0}}, 'color', v)` can leave the placeholder black stored on the paint, and the swatch renders black even though it's bound. Pass the variable's resolved value as `color` when binding.

**Variant labels sharing a TEXT component property share styling** (2026-10-15): if every variant's label references the same text property (e.g. Button "Label#…"), setting textDecoration (and likely other text styling) on one variant's label changes all of them. To style one variant differently, its label must not reference the shared property, which would reset instances' label overrides. Check `componentPropertyReferences` first.

**Hug before resize, not after:** `resize()` on a new auto-layout component resets `primaryAxisSizingMode` to FIXED. Set `primaryAxisSizingMode='AUTO'` AFTER `resize()`, or the instances get clipped.

**figma.flatten() inside a component lands at page coordinates** (2026-10-15): flattening outlined shapes into a component inside a frame put the result at x≈-3767. Set x/y explicitly after `flatten()`/`subtract()`.
